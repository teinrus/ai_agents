# API на FastAPI

HTTP — тонкий вход поверх уже принятых решений. В этом репозитории API на FastAPI. Каркас Django здесь не используется.

API появляется, когда он нужен спеке этапа, а не вместе с первым автоматом. До панели допустимо тонкое чтение задач и ленты, если оно нужно проверке ядра.

## Форма кода

Пакет `api` — единственный HTTP-край. Роут проверяет вход, вызывает сервис приложения, возвращает схему.

Сервис не содержит правил риска, выбора модели и оценки. Он вызывает оркестратор и читает ленту.

Доменные ошибки становятся ответами на краю. `NoModelError` и ожидание подтверждения — различимые результаты прогона, не необработанный сбой сервера.

Типы SDK провайдера в схемах ответа не появляются. Наружу — поля конверта событий и состояние прогона.

Корень сборки внедряет порты. Роут сам не создаёт адаптер и не читает секрет.

Настройки процесса — из окружения, с явным отказом старта, если включённому адаптеру не хватает переменной.

## Что API делает с подтверждением

Клиент присылает одноразовое подтверждение на ожидающий прогон. API передаёт его в политику. API инструмент не вызывает.

## Чего не делать

- Бизнес-ветка домена в обработчике маршрута.
- Отдельный протокол событий для HTTP, отличный от шины.
- Эндпоинт, который существует только для почты, в общем API. Доменный ресурс принадлежит плагину роли, если он вообще нужен.

## Готово, когда

- Выключение роутера оставляет OpenAPI и схемы ленты прежними по контракту событий.
- Тест API поднимает приложение на моках.
- По коду `api` нельзя понять, какая роль демонстрационная.
