# Архитектура платформы

Источник правды после появления файлов: `docs/architecture.md` и `docs/roadmap.md`. Этот файл говорит, как их соблюдать при разработке.

## Что строится

Общий каркас, в который роль входит конфигурацией: жизненный цикл, evaluation, память, шлюз инструментов, шина событий, абстракция LLM и model router.

Почта подключается, когда каркас уже стоит. Отсутствие почтовой роли не ломает ядро.

## Границы модулей

Имена пакетов, когда дойдёт до кода: `domain`, `orchestrator`, `runtime`, `evaluation`, `memory`, `tools`, `llm`, `events`, `observability`, `api`. Роли — плагины в `roles/<role_id>/`. Каталог ролей ядро вызывает через реестр. Пакет роли ядро не импортирует.

Направление зависимостей:

- `domain` ни от кого из платформы не зависит.
- Оркестратор ведёт прогон и не вызывает модель и инструменты сам.
- Runtime исполняет общий автомат и получает порты снаружи.
- Evaluation, memory, tools, llm, events — порты. Их реализации подменяемы.
- HTTP и React сидят снаружи и не владеют правилами.

Состав корня собирает один composition root: какие адаптеры, какой backend памяти, какой каталог моделей. Агент подключение не открывает.

## Что считать сменой платформы

Платформенная правка меняет контракт, которым пользуются все роли: состояние, событие, раздел памяти, уровень риска, требования к модели.

Правка роли меняет score, список скиллов, потолок риска и обработчики инструментов этой роли. Если для новой роли пришлось изменить оркестратор — это провал этапа, а не «особый случай».

## Антипаттерны

- Ветки `if role == mail` в runtime, роутере, памяти, evaluation.
- Типы «письмо», «ящик», «SMTP» в ядре.
- Прямой вызов SDK модели из роли.
- Пустые пакеты «на все будущие провайдеры».
- Панель, которая сама решает, можно ли отправить действие.

## Критерий этапа

- Этап 0: в репозитории только спеки, без каркаса приложения.
- Этап 1: ядро проходит тесты на моках; демонстрационная роль подключена последней через реестр.
- Этап 2: вторая роль на том же runtime. Смена модели первой роли — правка каталога.
- Этап 3: UI читает ленту и те же события. Ядро не переписано.
- Этап 4: новая реализация порта не меняет публичный контракт этапов 1–3.
