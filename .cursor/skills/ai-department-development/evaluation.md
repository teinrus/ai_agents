# Evaluation

Отдельный контур со своими событиями. Это не ветка внутри агента и не пункт доменного скилла.

## Когда запускается

Runtime закончил порцию работы и перевёл прогон в `Evaluating`. На вход контура: задача, выход, трасса. Оценщик инструменты не вызывает и модель сам не выбирает.

Пропуск контура запрещён. Без завершённой оценки результат клиенту как успех не отдаётся.

## Цикл

Лимит `max_revisions` берётся из ограничений задачи. Платформенный дефолт — одна правка, не бесконечный диалог.

1. `evaluation.started`.
2. `Evaluator.evaluate` → `passed` или `rejected` и список проверок.
3. `evaluation.completed` с вердиктом — при любом исходе.
4. `passed` — прогон можно отдавать клиенту. Состояние `Completed`, сотрудник в `Idle`.
5. `rejected` и правки ещё есть — `evaluation.revision_requested` со структурированными замечаниями. Runtime возвращает агента в `Running`. Модель и инструменты снова только через свои шлюзы.
6. Правки кончились — состояние `Failed`, статус прогона `rejected`. Под видом `completed` не публиковать.

## Первые проверки

Детерминированные и без домена:

- выход совпал со схемой роли;
- лимит шагов соблюдён;
- нет действия без требуемого подтверждения;
- нет вызова выше потолка риска;
- роль совпала с выбранной.

## Готово, когда

- Успешный прогон в ленте имеет `evaluation.completed` раньше `task.finished`.
- Исчерпанный лимит правок не выглядит как успех.
- Доменная роль не содержит собственного «я сама себя оценила».
