# Абстракция LLM-провайдера

Агент и роль не знают SDK, имя модели и секрет.

## Порт

`LlmProvider.complete(model_name, request)` выполняет один вызов.

Провайдер не читает требования задачи, не ранжирует модели и не публикует решение маршрута. Это работа роутера.

Ответ порта покрывает текст и запрошенные tool-calls. Тип SDK наружу не выходит.

## Первые адаптеры

- Mock — заранее заданные ответы и tool-calls. Его используют тесты ядра.
- Один локальный адаптер к OpenAI-совместимому endpoint. Имя модели берётся из каталога, не из константы в роли.
- Один облачный адаптер того же протокола, этап 4. Отдельный `provider_id` и строка каталога. Не пакет вендоров.

Новый провайдер = новый адаптер + строка каталога. Код агентов не меняется.

## Секреты и сбои

Ключ и базовый URL читает адаптер из окружения в composition root. В запрос модели, в событие и в память секрет не кладётся.

Сбой провайдера — ошибка вызова с типом и коротким сообщением. Роутер не подменяет модель молча, если каталог уже выбрал конкретную.

## Готово, когда

- Тест ядра идёт через mock и не открывает сеть.
- Локальный адаптер можно выключить конфигурацией, не трогая роли.
- Поиск по коду ролей не находит имя SDK и `model_id`.
