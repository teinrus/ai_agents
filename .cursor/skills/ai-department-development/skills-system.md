# Система скиллов сотрудников

Речь о каталоге платформы. Файлы `.cursor/skills/` сюда не входят и отсюда не читаются.

## Что такое скилл роли

Подключаемая способность роли: имя, инструкция для шага, связанные инструменты, какие требования к модели шаг обычно заявляет.

Оркестратор не знает почтовых имён. Он связывает список, который пришёл с выбранной ролью. Событие `skill.bound`.

Скилл не вызывает модель и не открывает сеть. Вызов модели идёт в роутер, вызов действия — в шлюз инструментов.

## Как добавлять умение

1. Описать скилл в плагине роли, не в ядре.
2. Инструменты скилла зарегистрировать с уровнем риска.
3. Проверить, что чужая роль этот скилл не видит, пока он не в её списке.
4. Не создавать Cursor skill с тем же именем.

Общая инструкция платформы («как устроен цикл») живёт в runtime. Доменная инструкция («как разобрать поручение этой роли») живёт в скилле роли.

## Граница с Cursor

| Вопрос | Куда |
| --- | --- |
| Как Cursor пишет шлюз инструментов? | `.cursor/skills/ai-department-development/` |
| Как сотрудник читает непрочитанное? | плагин роли, когда платформа уже стоит |
| Правило на все сессии IDE | `.cursor/rules/` |

Путаница этих строк — дефект. Исправлять переносом, а не дублированием текста в оба места.

## Готово, когда

- Роль без скиллов не получает чужие инструменты.
- Новый скилл не требует правки оркестратора.
- В `.cursor/` нет инструкций, которые должен исполнять runtime сотрудника.
