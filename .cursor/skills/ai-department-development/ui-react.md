# UI на React

Панель — будущий подписчик той же ленты и тех же конвертов. Пока этап UI не открыт, не создавать каркас фронтенда, клиент и пустое приложение.

## Модель экрана

Источник правды — лента прогона и события шины. Компонент не выводит политику заново и не выбирает модель.

Общие экраны платформы, не почтового продукта:

- состояние агента в общем автомате;
- развилка роутера: требования, выбранная модель, отклонённые кандидаты;
- решение инструмента: `allow`, `confirm`, `deny`;
- шаги evaluation и вердикт.

Доменные поля роли рисует только представление этой роли, если они есть в payload. Оболочка панели их не знает.

Подтверждение в UI отправляет в API одноразовый токен. Кнопкой нельзя вызвать инструмент напрямую.

## Как подключать

Новый подписчик ленты не меняет жизненный цикл, политику и роутер. Если для экрана не хватает поля, сначала добавляется поле конверта в спеке и в шине, затем экран.

Тексты интерфейса можно держать на русском. Имена событий и состояний остаются как в контракте.

## Чего не делать

- Второй журнал, который пишется только для UI.
- Экран «входящие» как главный каркас продукта.
- Дублирование `max_revisions`, потолка риска и каталога моделей в состоянии браузера как в источнике истины.

## Готово, когда

- Панель показывает прогон на моках без живой почты.
- Смена роли не требует новой оболочки, только данные ленты.
